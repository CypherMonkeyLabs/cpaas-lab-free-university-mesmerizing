Learn it in 5 minutes

  • SIP sets up the session. RTP carries the media. The webhook tells your app that something happened.
  • Twilio's voice docs also name Media Streams and a WebSocket for consuming a real-time stream.
  • Bandwidth returns 202 when a message is queued, then a delivered or failed webhook.
  • A SIP trunk's private and public domains still apply when the IVR is hosted.
  • No customer packet capture was opened. Every ladder in this lab is a teaching sketch.

Flow

What is going on

Put the arrows in an order you can defend. Registration and session setup, then media, and in parallel the HTTP event to your application if the platform is programmable. Media Streams are a third path: media copied to a WebSocket, named on Twilio's voice navigation. This session did not open the WebSocket message schema, so the field list stays confirm.

Do not draw a transfer unless you have a verb. Twilio lists Refer and Dial. A warm transfer's exact header sequence was not copied from an RFC in this room. RFC 3261 is the signaling specification. A vendor's transfer tutorial was not opened, so the click path is confirm.

Worked example

Sketch: caller, platform, your webhook, agent. SIP between caller and platform, RTP as a dashed line that need not hairpin, HTTP from the platform to your app. Stop. Add Refer only as a named verb, not as a captured call.
